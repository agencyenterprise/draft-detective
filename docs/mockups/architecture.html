1 · Inputs

A project

  • Main document
    .docx, .pdf, .md, .txt; one per revision
  • Supporting sources
    full texts of cited references, uploaded or fetched
  • Reviewer memos
    for the peer-review reports

2 · Pipeline steps

Shared preparation

  1. Markdown conversion
    one line-numbered text that every finding points into; images and charts kept as viewable references
  2. Reference extraction
    the bibliography as structured entries
  3. Source matching & download
    pairs each reference with its full text; the author confirms before claim checks run

3 · Assessments

Independent checks, run in parallel

Skill SKILL.md

The rules for one kind of review, in plain language. The same file runs in the app and installs on its own in Claude or Codex.

Agent

Reads the document through tools and reports each finding as it goes.

read & search document view images web search source retrieval subagents

Citation, substantive, editorial and language checks. Each is picked separately or through a preset.

4 · One output shape

Issues

title
description
severity high · medium · low · none
start_line / end_line
suggested_action
edits[] exact text swaps

Every check reports the same shape, anchored to lines of the document, so every surface can show any check's findings. Some checks also write a report.

5 · Where findings go

Surfaces

  • Web app
    Document Explorer, assessments, read-only share links
  • Word export
    issues as comments, proposed edits as tracked changes
  • Word add-in
    findings beside the paragraphs in Word
  • MCP server
    run checks and read results from any MCP client
